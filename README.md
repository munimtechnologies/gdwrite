# gdwrite 0.2.0

Write GDevelop 5 project files from code, with no editor open: one scene, Sprite and Text objects,
GDevelop's built-in behaviors (such as the platformer ones), instances, image and sound resources and
JavaScript code events. `png.mjs` makes simple sprite images and `wav.mjs` simple sound effects in
code (no dependencies), so a whole test scene can be generated by a script. Needs Node.js 18 or later.

## How it works

GDevelop's project format has many fields that change between versions. gdwrite does not hard-code
them: `loadTemplates()` reads one or more example projects that GDevelop itself saved (for example
the official GDevelop examples) and clones a scene, a layer, a Sprite, a Text object, an instance,
an image resource and every behavior it finds from them. You then fill in only what you want: names,
images, sounds, behavior settings, positions and event code.

```js
import fs from "node:fs";
import { loadTemplates, behaviorTypes, spriteObject, textObject, withBehavior, imageResource, audioResource,
  instance, jsEvent, buildProject } from "./gdwrite.mjs";
import { shapePNG } from "./png.mjs";
import { blipWAV } from "./wav.mjs";

const t = loadTemplates(["breakout.json", "platformer.json"].map((f) => JSON.parse(fs.readFileSync(f, "utf8"))));
console.log(behaviorTypes(t)); // the behavior types the examples contain
fs.writeFileSync("player.png", shapePNG(32, 32, [80, 170, 255], "box"));
fs.writeFileSync("ground.png", shapePNG(32, 32, [90, 200, 120], "box"));
fs.writeFileSync("blip.wav", blipWAV({ f0: 520, f1: 880, ms: 120 }));
const project = buildProject(t, {
  name: "my game", packageName: "com.example.mygame", width: 800, height: 600, bg: [24, 40, 72],
  resources: [imageResource(t, "player.png"), imageResource(t, "ground.png"), audioResource(t, "blip.wav")],
  objects: [
    withBehavior(t, spriteObject(t, "Player", "player.png"), "PlatformBehavior::PlatformerObjectBehavior", "PlatformerObject"),
    withBehavior(t, spriteObject(t, "Ground", "ground.png"), "PlatformBehavior::PlatformBehavior", "Platform"),
    textObject(t, "Hud", { text: "Hello" }),
  ],
  instances: [instance(t, "Player", 100, 100, 1), instance(t, "Ground", 80, 400, 2, 1, { width: 640, height: 32 }), instance(t, "Hud", 24, 24, 3)],
  events: [jsEvent("if (runtimeScene.getObjects('Player')[0].getBehavior('PlatformerObject').isJumping()) {}")],
});
fs.writeFileSync("game.json", JSON.stringify(project, null, 2));
```

`withBehavior(t, object, type, name, props)` only accepts properties the example's behavior already
has, so a misspelt setting fails when the project is written, not later in the engine. The scene's
behavior shared data is filled in for you. A sound is played from a JavaScript event with
`gdjs.evtTools.sound.playSound(runtimeScene, "blip.wav", false, 60, 1)`.

Two complete examples:

- `node build-demo.mjs <out dir> <example.json> [...]`: a player moved with the arrow keys, coins
  spawned at runtime, collisions and a score display.
- `node build-platformer.mjs <out dir> <example.json> [...]` (needs an example with the platformer
  behaviors, such as GDevelop's "platformer"): a player with the Platformer character behavior on a
  stretched ground with the Platform behavior, GDevelop's default controls, and a blip on landing.

The example projects are not included; get them from
https://github.com/GDevelopApp/GDevelop-examples (`examples/breakout/breakout.json` and
`examples/platformer/platformer.json` were used in the tests below).

## What was tested

- `node --test test_gdwrite.mjs` (or `npm test`): 16 unit tests (PNG and WAV encoding, template
  loading, objects, behaviors, shared data, sounds, instances, project).
- In an automated sandbox on 2026-10-18 (Node 20), all 16 tests passed on these files, both from the
  source folder and again from a clean unzip of gdwrite-0.2.0.zip. Both example scenes, built with
  templates from GDevelop's breakout and platformer examples, were exported for the web with
  gdcore-tools 2.0.0-gd-v5.6.269-autobuild and played in headless Chromium with no page errors. Coin
  demo: images loaded, coins spawned, the arrow keys moved the player and a coin was collected.
  Platformer demo: the player fell onto the stretched ground and stopped on it, walked with the Right

- The step that committed these files to GitHub does not run Node, so the tests were not re-run at
  commit time; run `npm test` to check them yourself.

## Limits

- One scene; Sprite and Text objects; image and sound resources; JavaScript events. No regular
  (non-code) events, fonts, tilemaps or physics yet.
- Behaviors must be ones GDevelop ships with and must appear in an example you supply. Behaviors from
  custom extensions are not copied, because the extensions themselves are not.
- Fonts are left empty, so text uses GDevelop's default font.
- Templates come from projects you supply; fields GDevelop adds in later versions are whatever those
  projects contain.

## Prior art

Other people have built tools for working with GDevelop projects from code, among them GDevelop's
own command-line tools, gdcore-tools / gdexporter (exporting without the editor, used in the tests
above) and MCP bridges that let AI assistants edit GDevelop projects. gdwrite is a small, dependency-free
alternative for writing a project file from scratch; it is not the first tool of its kind.
